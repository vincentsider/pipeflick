  <name>Speaker filter</name>
  <files>src/speaker-filter.ts, test/speaker-filter.test.ts, vitest.config.ts, package.json</files>
  <behavior>
    Framework setup (part of RED): `npm i -D vitest` (5.x on npm today), add `"test": "vitest run"` to package.json scripts, create `vitest.config.ts` with `test: { include: ["test/**/*.test.ts"] }`. Tests live in `test/`, outside tsconfig's `include: ["src"]`, so `npm run check` is untouched and Plan 02-02 (running in parallel) is not affected by a half-installed vitest. Do not add `@cloudflare/vitest-plugin`; the module under test is pure.

    Types exported from `src/speaker-filter.ts`:
    - `Sentence = { index?: number | null; speaker_name?: string | null; text?: string | null; raw_text?: string | null }` (mirrors the Fireflies `sentences` fields used in 02-03).
    - `SpeakerCount = { label: string; lines: number }`.

    `normaliseLabel(s: string | null | undefined): string` (exported, used by the others): trim, collapse internal whitespace to one space, lowercase. `null`/`undefined` → "".

    `countBySpeaker(sentences): SpeakerCount[]`
    - one entry per distinct normalised label, `label` is the first-seen original (trimmed) spelling; empty/null speaker_name counts under label "Unknown"
    - only sentences with non-blank text (see sentenceText below) are counted
    - ordered by `lines` descending, ties by first appearance

    `matchSpeaker(labels: string[], configured: string | null | undefined): string | null`
    - returns the original label (not the normalised form)
    - configured blank → null
    - exact normalised match wins ("vincent sider" vs "Vincent  Sider" → match)
    - otherwise, if exactly one label's normalised form contains the normalised configured name ("Vincent" → "Vincent Sider"), return it
    - if two or more labels contain it (e.g. "Vincent Sider" and "Vincent Smith") → null (ambiguous; the user picks on the preview page)
    - "Speaker 1"/"Speaker 2" style labels with configured "Vincent" → null

    `keepSpeakerLines(sentences, label: string): string[]`
    - keeps only sentences whose normalised speaker_name equals the normalised label
    - preserves input order (sort by `index` when every kept sentence has one; otherwise keep array order)
    - each line is `sentenceText(sentence)`: `text` if non-blank, else `raw_text` if non-blank; blank lines are dropped; lines are trimmed
    - never returns any text from another speaker; the test asserts the joined output does not contain the other speakers' words
    - empty input or no matching speaker → []

    Cases the test file must cover (one `it` per case):
    1. keeps only the chosen speaker's lines, in order, from a 3-speaker sample
    2. matching is case and whitespace insensitive
    3. returns [] when the label matches nobody
    4. uses `text`, falls back to `raw_text`, drops blank sentences
    5. output contains no words from other speakers (negative assertion)
    6. countBySpeaker counts lines and orders by count descending, "Unknown" for missing names
    7. matchSpeaker exact match beats partial match
    8. matchSpeaker unique partial match ("Vincent" → "Vincent Sider")
    9. matchSpeaker ambiguous partial → null
    10. matchSpeaker blank configured name → null; generic "Speaker 1" labels → null
  </behavior>
  <implementation>
    Plain TypeScript, no dependencies, no I/O, no logging. Keep functions small and exported individually (named exports, no default). Add a two-line module comment stating that this is the only place that decides what transcript text may be stored and that other speakers' text must not leave this function. Use `Map` for counting; sort with a stable comparator. Node 26 runs vitest natively; if `npm test` fails on TS syntax, set `esbuild` target in vitest.config.ts to `es2022`.
  </implementation>
</feature>
