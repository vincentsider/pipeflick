<task type="auto">
  <name>Task 2: Account deletion</name>
  <files>src/db.ts, src/settings.tsx</files>
  <action>
    Add `deleteAccount(db, owner)` to `src/db.ts`: delete every row that account owns, children
    first — drafts and outliers via their runs, then runs, transcripts, voice_samples,
    account_credentials, and settings. Return the counts deleted per table so the caller can
    report what actually went, rather than claiming success.

    Children carry no owner column (06-01), so they must be deleted by their run ids, read
    first. Deleting runs before their children would orphan the children permanently — there
    would be no owner and no run to find them by. Write that ordering constraint as a comment;
    it is the kind of thing a later refactor reverses without noticing.

    Add the control to /settings behind a typed confirmation (the account's own email address),
    not a single button. It is irreversible and there is no undo.

    After deletion, end the session by redirecting to the Cloudflare Access logout path so the
    user is not left signed in to an account that no longer has anything.
  </action>
  <verify>
    Seed two accounts with full data — transcripts, samples, a run with outliers and drafts and
    decisions, credentials, settings. Delete one. Then measure: every table has zero rows for
    that owner, the OTHER account's row counts are completely unchanged, and no orphaned
    outlier or draft remains (`SELECT COUNT(*) FROM drafts WHERE run_id NOT IN (SELECT id FROM runs)`
    is 0). Paste the before/after counts into the SUMMARY.
  </verify>
  <done>An account can erase itself completely, and doing so leaves every other account intact.</done>
