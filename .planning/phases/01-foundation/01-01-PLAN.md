1. `package.json`: name `pipeflick`, `"private": true`, `"type": "module"`. Scripts:
   - `dev`: `wrangler dev`
   - `deploy`: `wrangler deploy`
   - `types`: `wrangler types`
   - `check`: `wrangler types && tsc --noEmit`
   - `db:migrate:local`: `wrangler d1 migrations apply pipeflick-db --local`
   - `db:migrate:remote`: `wrangler d1 migrations apply pipeflick-db --remote`
   Dependencies: `hono` (^4.13). Dev dependencies: `wrangler` (^4.131), `typescript` (^5). Do not add `@cloudflare/workers-types`; `wrangler types` generates runtime types including `ExecutionContext.access`, which Plan 01-02 relies on.
2. `tsconfig.json`: `target` ES2022, `module` ESNext, `moduleResolution` Bundler, `strict` true, `noEmit` true, `jsx` `react-jsx`, `jsxImportSource` `hono/jsx`, `types: ["./worker-configuration.d.ts"]`, `include: ["src"]`.
3. `wrangler.jsonc`: `name` `pipeflick`, `main` `src/index.tsx`, `compatibility_date` `2026-09-01` (not today's date; a future date is rejected), `compatibility_flags: ["nodejs_compat"]`, `observability: { enabled: true }`, `preview_urls: false` (preview hostnames would bypass the hostname-based Access gate added in Plan 01-02). No `assets` binding, now or later in this phase: static assets run behind a router Worker that drops the Access context. The `d1_databases` block is added in Task 2.
4. `src/layout.tsx`: a `Layout` function component (`FC<PropsWithChildren<{ title: string }>>` from `hono/jsx`) that renders `<html>` with a `<title>`, a small inline `<style>` (system font, max-width 720px, simple table styling) and a header "Pipeflick". Inline CSS only.
5. `src/index.tsx`: `const app = new Hono<{ Bindings: Env }>()`; `GET /` renders `<Layout title="Pipeflick"><p>Pipeflick is running.</p><p><a href="/health">Health</a></p></Layout>` via `c.html(...)`. `export default app`. `/health` itself is built in Plan 01-03; the link may 404 for now.
6. `.gitignore`: keep `.env` and `.mcp.json`; add `node_modules/`, `.wrangler/`, `.dev.vars*`, `worker-configuration.d.ts`, `dist/`.
7. `CLAUDE.md`: replace the "Current state" paragraph (which says there is no application code or commands) with a short "Commands" section listing the scripts above and stating the stack (Cloudflare Worker, Hono + hono/jsx, D1, wrangler). Leave the rest of CLAUDE.md untouched.
8. `npm install`, then `npm run check`.

Run `npm run dev` in the background, `curl -s http://localhost:8787/` and stop the dev server afterwards. Note: wrangler also loads the root `.env` (unrelated Supabase password) as a local var; harmless, but never reference it.

<task type="auto">
  <name>Task 2: Create the D1 database, first migration and settings helpers</name>
  <files>wrangler.jsonc, migrations/0001_settings.sql, src/db.ts</files>
  <action>
1. Run `npx wrangler d1 create pipeflick-db`. If it reports the name already exists, take the id from `npx wrangler d1 list --json` instead. Add to `wrangler.jsonc`: `d1_databases: [{ binding: "DB", database_name: "pipeflick-db", database_id: "<uuid>" }]`.
2. Create `migrations/0001_settings.sql` (wrangler's default `migrations/` directory, so no `migrations_dir` key is needed):
   `CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at TEXT NOT NULL);`
   Phase 1 deliberately creates only this table. Transcripts, samples, runs and drafts get their own migrations in their own phases.
3. `src/db.ts`: export `getSetting(db: D1Database, key: string): Promise<string | null>` and `setSetting(db: D1Database, key: string, value: string): Promise<void>`. Use `db.prepare("...").bind(...)` with placeholders for every value (no string interpolation into SQL). `setSetting` uses `INSERT INTO settings (key, value, updated_at) VALUES (?1, ?2, ?3) ON CONFLICT(key) DO UPDATE SET value = excluded.value, updated_at = excluded.updated_at` with `new Date().toISOString()`.
4. Apply: `npm run db:migrate:local` then `npm run db:migrate:remote`. The remote apply may ask for confirmation when run in a terminal; in a non-interactive shell it proceeds. If it does prompt, answer yes.
5. `npm run check` (the generated `Env` now includes `DB: D1Database`).

Do not run `wrangler d1 execute --remote` with anything other than a `SELECT`; remote changes cannot be undone.
  </action>
  <verify>`npx wrangler d1 execute pipeflick-db --remote --command "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"` lists `d1_migrations` and `settings`; the same with `--local` lists both; `npm run check` exits 0</verify>
  <done>D1 bound as DB, migration 0001 applied locally and remotely, typed helpers exported from src/db.ts</done>
</task>
