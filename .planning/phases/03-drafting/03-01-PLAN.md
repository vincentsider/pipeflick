<objective>
Build `src/prompts.ts`: the pure, I/O-free module that assembles every OpenAI payload for
this phase, holds both strict JSON schemas and both instruction strings, and provides the
mechanical grounding check for DRAFT-03.

Purpose: this module is the compliance boundary. Because it takes primitives only, there is
no code path that can send a Fireflies meeting title (which routinely names a counterparty),
a speaker label, or another participant's words to OpenAI. Making that structurally
impossible — and asserting it in a test — is the Jersey/JFSC constraint enforced in code
rather than in a policy document.

Output: `src/prompts.ts` and `test/prompts.test.ts`, written test-first.
</objective>

<feature>
  <name>Prompt assembly, schemas and grounding check</name>
  <files>src/prompts.ts, test/prompts.test.ts</files>

  <behavior>
  Exported surface (all pure, no I/O, no logging, no env access):

  Constants — from 03-RESEARCH.md "Standard Stack" and "Common Pitfalls 7":
    MODEL_EXTRACT = "gpt-5.6-terra"      MODEL_DRAFT = "gpt-5.6-sol"
    MAX_OUTPUT_EXTRACT = 4000            MAX_OUTPUT_DRAFT = 8000
    TIMEOUT_EXTRACT_MS = 60_000          TIMEOUT_DRAFT_MS = 120_000
    MAX_OUTLIER_CHARS = 5000             MAX_TRANSCRIPT_CHARS = 12000
    MAX_SAMPLE_CHARS = 2500              MAX_SAMPLES = 3

  Types:
    Template = { hook: string; structure: string[]; angle: string }
    DraftOutput = { post: string; source_lines: string[] }

  TEMPLATE_SCHEMA / DRAFT_SCHEMA — copy verbatim from 03-RESEARCH.md "Code Examples".
    Both: root `type: "object"`, every property listed in `required`,
    `additionalProperties: false`. DRAFT_SCHEMA lists `post` before `source_lines`
    (strict mode generates in key order, so the post is written before its citations).

  EXTRACT_INSTRUCTIONS / DRAFT_INSTRUCTIONS — copy verbatim from 03-RESEARCH.md
    "Prompt Design" (a) and (b). Do not paraphrase or shorten them; the banned-word list,
    the "invent nothing" grounding rules and the "never mention a transcript/meeting/AI"
    rule are all load-bearing.

  excerptTranscript(body: string): { text: string; linesUsed: number; linesTotal: number }
    - splits on "\n", keeps whole lines while the running length stays within
      MAX_TRANSCRIPT_CHARS, never cuts mid-line
    - short body -> text === body, linesUsed === linesTotal
    - a single line longer than the cap -> that line hard-truncated, linesUsed 1
    - empty body -> text "", linesUsed 0, linesTotal 0

  buildExtractionInput(outlierBody: string): string
    - returns "<outlier_post>\n{body sliced to MAX_OUTLIER_CHARS}\n</outlier_post>"

  buildDraftingInput(samples: string[], transcriptBody: string, template: Template): string
    - PRIMITIVES ONLY. Never accepts a TranscriptRow, a Meeting, or any object with a
      title or speaker field. This signature is the compliance guarantee.
    - blocks in exactly this order, because everything before <format> is the
      prompt-cache prefix shared across all three drafting calls:
        <voice_samples> ... </voice_samples>
        <transcript> ... </transcript>
        <format> {JSON.stringify(template)} </format>
    - samples: at most MAX_SAMPLES, each sliced to MAX_SAMPLE_CHARS, joined by "\n---\n"
    - zero samples -> the <voice_samples> block still renders, empty, so the cache
      prefix shape stays stable
    - transcript: passed through excerptTranscript

  isGrounded(transcriptBody: string, sourceLines: string[]): boolean
    - true when every entry is a non-empty substring of transcriptBody
    - empty array -> false (a draft citing nothing is not grounded)
  </behavior>

  <implementation>
  Plain exported functions and `as const` schema objects. No classes, no dependencies.
  Instruction strings as module-level template literals.

  Do NOT import anything from src/db.ts, src/fireflies.ts or src/speaker-filter.ts —
  this module must have zero imports so that nothing carrying a title or a speaker label
  is even reachable from here.
  </implementation>
</feature>
