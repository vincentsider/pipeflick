<objective>
Tell the executive how much of their transcript was actually used.

Purpose: Closes Gap 2 of 03-VERIFICATION.md. `MAX_TRANSCRIPT_CHARS` silently dropped roughly a
third of an 18,429-character meeting on production run 1. `excerptTranscript` already computes
`linesUsed` and `linesTotal` precisely — 03-01 built them for exactly this sentence — but no
page in `src/` consumes either value, so the only evidence the executive has that two thirds of
their words were used is drafts that feel thin.

Output: migration 0004, the counts stored on the run at creation, a pre-run warning on any
transcript that will be cut, and the exact figure on the run page.

Secondary win: `POST /runs` currently loads the whole transcript body only to prove the row
exists and then discards it (recorded as a minor concern in STATE.md). That read becomes useful
instead of wasted.

Scope boundary: this plan does NOT touch `src/prompts.ts` — 03-05 is editing it in the same
wave, and `excerptTranscript` is used here exactly as it stands. Migration 0004 also adds
`drafts.grounding_json`, which 03-07 fills; adding both columns in one migration means the
remote D1 is altered once rather than twice.
</objective>

<task type="auto">
  <name>Task 2: Store the coverage and expose it to the views</name>
  <files>src/db.ts</files>
  <action>
1. `RunRow` gains `transcript_lines_used: number | null` and `transcript_lines_total: number | null`.
   Null is a real state (every run so far), not a defect — type it that way and let it reach the UI.

2. `createRun(db, transcriptId, outlierBodies, coverage: { linesUsed: number; linesTotal: number })`.
   Take the two counts as primitives and write them in the `INSERT INTO runs`. Do NOT import
   `excerptTranscript` here: 03-02 established that `src/db.ts` imports nothing from
   `src/prompts.ts`, and that boundary is what keeps the prompt builders provably free of row
   types. The caller computes; this function stores.

3. `getRunView` selects both new columns in its `runs` query so they land on `RunView.run`.
   Leave the rest of the projection exactly as it is — `template_json` stays unselected and
   `outliers.body` stays behind `substr`.

4. `listTranscripts` additionally selects `length(body) AS body_chars`, and `TranscriptSummary`
   becomes `Omit<TranscriptRow, "body"> & { body_chars: number }`. The body itself still never
   leaves D1; only its length does. This is what lets the new-run form warn before a run is
   paid for. `src/sources.tsx` consumes the same type and is unaffected by the widening — confirm
   with `npm run check`, do not edit it.

Note in a comment beside `body_chars` that SQLite `length()` counts characters and
`MAX_TRANSCRIPT_CHARS` is compared against JavaScript `string.length`, so the two agree for
ordinary transcript text and the form uses it only as a threshold, never as a displayed figure.
  </action>
  <verify>`npm run check` exits 0. `npm test` still passes 34/34 (no test touches these helpers).</verify>
  <done>A run row can hold its coverage, `getRunView` returns it, and the transcript list carries a body length without carrying a body.</done>

<task type="auto">
  <name>Task 3: Compute it at run creation, show it before and after</name>
  <files>src/runs.tsx</files>
  <action>
**`POST /runs`** — the transcript is already loaded here to prove it exists. Use it:
```ts
const { linesUsed, linesTotal } = excerptTranscript(transcript.body);
const runId = await createRun(c.env.DB, transcriptId, bodies, { linesUsed, linesTotal });
```
Import `excerptTranscript` from `./prompts` alongside the existing imports. Drop the comment
that calls the read wasteful, if one is there.

**`NewRunForm`** — mark the transcripts that will be cut, using `row.body_chars` against
`MAX_TRANSCRIPT_CHARS`:
- In the `<option>` label, append ` (long — only the first part is used)` when
  `row.body_chars > MAX_TRANSCRIPT_CHARS`.
- Add one `class="hint"` line under the select: `Long meetings are cut to the first
  {MAX_TRANSCRIPT_CHARS} characters, on a line boundary. The run page shows exactly how much
  was used.`
Deliberately no numbers in the option label: the exact figure is lines-based and comes from the
run page, and two different units on two pages is how a user stops trusting both.

**Run page (`GET /runs/:id`)** — a new component beside `StepStatus` and `Failure`:
```tsx
function TranscriptCoverage({ used, total }: { used: number | null; total: number | null })
```
- Either value null → render `""`. A run created before migration 0004 has no coverage figure,
  and inventing one would be exactly the over-claiming this gap exists to fix.
- `used >= total` → `<p class="hint">Using all {total} lines of your transcript.</p>`
- `used < total` → `<p class="notice warn">Using the first {used} of {total} lines of your
  transcript. The rest was not sent. Shorter meetings, or splitting a long one, give the drafts
  more to work with.</p>`

Render it immediately after the `{done} of {total} steps done` paragraph and before
`<RunControl>`, so it is above the fold while the run is still generating and still there when
the drafts are read.
  </action>

- Open an existing pre-0004 run (local) and confirm no coverage line appears and the page does
