<task type="auto">
  <name>Task 1: The step route — one claim, one OpenAI call</name>
  <files>src/runs.tsx</files>
  <action>
    `POST /runs/:id/step`, following 03-RESEARCH.md "The step route".

    Shape, in order:
    1. If `c.env.OPENAI_API_KEY` is missing, render a 500 pointing at `/health` and make no
       request — the same guard `src/fireflies-routes.tsx` uses for its key.
    2. `claimNextJob(db, runId)`. If it returns null, 303 back to `/runs/:id` — the run is
       finished, or every remaining job has failed. Never call OpenAI without the claim: a
       double-click or a second tab would otherwise pay twice.
    3. Extraction branch (`kind === "extract"`): `callStructured&lt;Template&gt;` with
       `MODEL_EXTRACT`, `EXTRACT_INSTRUCTIONS`, `buildExtractionInput(outlierBody)`,
       schema name "outlier_template", `TEMPLATE_SCHEMA`, `MAX_OUTPUT_EXTRACT`,
       `TIMEOUT_EXTRACT_MS`. Then `finishOutlier(db, id, value, usage)`.
    4. Drafting branch (`kind === "draft"`): read the transcript body with `getTranscript`
       and the samples with `listVoiceSamples`, then call `buildDraftingInput(samples, body,
       template)`. Pass PRIMITIVES — `transcript.body`, the sample bodies as `string[]`, and
       the template. Never pass the `TranscriptRow`: its `title` routinely names a
       counterparty, and sending it is the JFSC/Jersey failure this phase is designed to
       prevent. Call with `MODEL_DRAFT`, `DRAFT_INSTRUCTIONS`, schema name "linkedin_draft",
       `DRAFT_SCHEMA`, `MAX_OUTPUT_DRAFT`, `TIMEOUT_DRAFT_MS`. Compute
       `isGrounded(transcript.body, value.source_lines)` and pass it to `finishDraft`.
    5. `catch`: narrow to `OpenAIError`, else a fixed `OpenAIError("Unexpected failure",
       "unknown", 0, false)`. `failJob(db, job, code, message)`. Never let a raw `Error` or a
       stack reach the page.
    6. Always `c.redirect(`/runs/${runId}`, 303)`, success or failure. POST -> 303 -> GET
       means a reload never re-fires a step.

    Keep the route under ~10 total subrequests plus D1 queries: Free-plan budgets are 50
    subrequests AND 50 D1 queries per invocation, and this route uses one of the former.
  </action>
  <verify>
    `npm run dev`, create a run, POST a step and confirm the outlier row reaches
    `status='done'` with `template_json` populated and `usage_json` recorded. POST again and
    confirm the next job advances. Force a failure by running once with a deliberately bad
    key in `.dev.vars`: the job must reach `status='failed'` with `error_code` set, and the
    page must show OpenAI's message with no stack.
  </verify>
  <done>One POST = one claim = one OpenAI call; results and failures both land on the job row.</done>
</task>

<task type="auto">
  <name>Task 2: Auto-advance and retry</name>
  <files>src/runs.tsx</files>
  <action>
    On the `GET /runs/:id` page built in 03-03, add:

    **The auto-advance form** (03-RESEARCH.md Pattern 2). A POST form to `/runs/:id/step`
    whose label reads "Continue (N of 6 done)", plus a `<script>` that submits it after a
    short delay. `dangerouslySetInnerHTML` is required — hono/jsx escapes text children,
    the same escape hatch 01-01 established for `<style>`. POST, not a meta refresh: a GET
    that spends money would be reachable from an `<img src>` and would sidestep the app-wide
    `csrf()` check.

    Render the auto-submit script ONLY when ALL of:
      - there is claimable work (a job not 'done' and not permanently failed), AND
      - the most recent failure, if any, was retryable, AND
      - that job's `attempts < 2`
    Otherwise render the form as a plain button with no script, or nothing at all. This
    guard is what stops a bad key from resubmitting forever and burning the Free plan's
    100,000 daily requests. When the failure carried `retryAfterSeconds`, use it as the
    `setTimeout` delay and say so on the page; otherwise ~400ms.

    **The retry button.** `POST /runs/:id/retry` calls `resetRunJobs(db, runId)` and 303s
    back. Show it whenever any job is failed. Label it so the cost is obvious: it re-runs
    only the steps that are not done, so completed calls are never re-paid for.

    **The finished state.** When all six jobs are done, no form and no script — just the
    three drafts, each with its grounding warning if any, and a note that Phase 4 will add
    accept/edit/reject.
  </action>
  <verify>
    `npm run dev`: start a run and leave the page open. It advances by itself through six
    steps to three drafts with no further clicks. Then set a bad key, start a run, and
    confirm the page stops after two attempts with an error and a manual Retry button —
    check the Worker request log to prove it is not looping. Retry after two successful
    extractions re-runs only the unfinished jobs.
  </verify>
  <done>A run walks itself to three drafts; a non-retryable failure stops cleanly with a manual retry.</done>
</task>
