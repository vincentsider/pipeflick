  <files>src/runs.tsx, src/index.tsx, src/layout.tsx</files>
  <action>
    New router `export const runs = new Hono&lt;AppEnv&gt;()`, mounted in `src/index.tsx`
    with `app.route("/", runs)` alongside the others, and a "Runs" entry in the `NAV` array
    in `src/layout.tsx` (between Sources and Fireflies). Add any new CSS to the `css` string
    in `layout.tsx` — that file owns all styling, and there is no client JS in this plan.

    `GET /runs` — `listRuns(db)` in a table: transcript title, created date, status, and
    "N of 6 done". Link each row to `/runs/{id}`. Empty state points at `/runs/new`.

    `GET /runs/new` — the form. Fields:
      - a `select` of `listTranscripts(db)` showing title and date, `required`
      - three `textarea`s named `outlier1`, `outlier2`, `outlier3`; the first two `required`,
        the third labelled optional. `maxlength` = the outlier cap from src/prompts.ts.
      - hint text: paste the full text of a post that performed unusually well. Say plainly
        that pasting is the only route — fetching LinkedIn posts by URL is out of scope and
        non-compliant (REQUIREMENTS.md "Out of Scope").
    If there are no transcripts, render a link to `/fireflies` instead of a dead form.

    `POST /runs` — validate before touching D1, returning a plain-text 400 like
    `src/sources.tsx` does:
      - transcript id matches `^[A-Za-z0-9_-]{1,100}$` AND `getTranscript` finds it
      - after trimming, between 2 and 3 non-empty outlier bodies
      - each body within the outlier cap
    Then `createRun(...)` and `c.redirect(`/runs/${id}`, 303)`. POST -> validate -> 303 is
    the established pattern; the app-wide `csrf()` Origin check already covers this route.
  </action>
  <verify>
    `npm run check` passes. With `npm run dev`:
    `/runs/new` lists imported transcripts; submitting with two outliers 303s to `/runs/{id}`;
    submitting with one outlier returns 400; an unknown transcript id returns 400.
    Then `npx wrangler d1 execute pipeflick-db --local --command "SELECT position, outlier_id, status FROM drafts"`
    shows exactly three pending rows for the run.
  </verify>
  <done>A valid submission creates one run, 2-3 outlier jobs and exactly 3 draft jobs, and lands on the run page.</done>

      - overall progress, "N of 6 steps done"
      - a "Templates" section listing each outlier by position with its status, attempts,
