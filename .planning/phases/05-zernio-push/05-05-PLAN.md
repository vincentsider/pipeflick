<objective>
Close gap 1 from 05-VERIFICATION.md: a failed push is written to D1 and shown nowhere.

Purpose: SCHED-03 and Phase 5 success criterion 3 ask that "a failed push shows a clear error".
`b954dc5` rebuilt the Run and Approve screens after 05-04 and removed `<DraftSection>`, which
orphaned `PushState` — the only reader of `zernio_error_code` and `zernio_error_message`. The
Approve screen, now the only place a push can start, never picked that job up, and the route's
failure and duplicate branches redirect to `/runs/:id`, which shows no push state at all. From
the executive's side, a push Zernio refuses looks like a button that did nothing.

Output: the failed-push state on the Approve screen, every push redirect returning to the draft,
and the orphaned components removed. **Not deployed** — the deploy is held for a decision about
the public site Worker (05-VERIFICATION.md gap 2), which this plan does not touch.
